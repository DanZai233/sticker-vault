# 表情仓 · StickerVault

把分散在聊天软件里的表情收进本地素材库，保留动图原件，通过拖拽、复制或菜单栏快捷面板再次使用。

> 当前为 0.6.0 版本。安装包跨平台构建与聊天软件的兼容性是两回事：Mac 的 QQ 个人收藏已实测；微信首次登录和抖音网页收藏仍有平台、账号和网络限制，详见支持表。

## 下载与安装

- 正式版本：仓库右侧 **Releases**，选择与你的系统和 CPU 对应的安装包。
- 开发版本：**Actions → Build desktop installers → 成功的运行 → Artifacts**，登录 GitHub 后下载平台构建产物，解压外层 artifact ZIP 后安装里面的文件。Artifacts 保存 14 天。

| 系统    | CPU                   | 文件                                             |
| ------- | --------------------- | ------------------------------------------------ |
| macOS   | Apple Silicon / Intel | `mac-arm64` / `mac-x64` 的 `.dmg` 或 `.zip`      |
| Windows | Intel/AMD / ARM64     | `win-x64` / `win-arm64` 的 `.exe`，NSIS 安装向导 |
| Linux   | x64 / ARM64           | 对应架构的 `.AppImage` 或 `.deb`                 |

安装包没有开发者证书签名或 macOS 公证，操作系统可能提示无法验证开发者。项目没有自动升级功能。Linux AppImage 可能需要发行版的 FUSE 兼容库，也可以安装 `.deb`。

## 第一次使用

1. 启动应用，点 **导入表情** 选择图片；也可以把文件或文件夹拖进窗口。
2. 在 **设置** 中连接 QQ、微信、抖音，或关联本地收集文件夹。
3. 卡片右下角 **♡ / ♥** 收藏或取消收藏；**↑** 将表情移到第一位，再点仍移到第一位，没有取消置顶状态。移动顺序会保存，后续导入或使用仍按对应列表自然排序。单击表情自动复制原文件；双击或右键打开详情，可修改名称、标签、常用状态及导出。
4. 在主窗口搜索名称、标签或来源；**最近使用** 展示点击复制、插入或尝试拖出的表情，也可按最近使用排序。
5. 拖动表情卡片或详情中的原图到聊天窗口；若接收软件不支持拖拽，使用 **复制原文件** 后粘贴，或导出后选择文件发送。

### 菜单栏 / 系统托盘快捷面板

点击菜单栏的表情图标，或按 `⌘ / Ctrl + Shift + E`，打开搜索与表情缩略图浮层。可切换最近使用、常用、全部，点击使用或直接拖出。悬停到图片或用键盘聚焦时，右下角显示收藏与移到第一位按钮；与主界面共用数据，点击这些按钮不会复制或插入表情。列表显示总数，采用可视区域渲染，滚动即可浏览全部，不受前 120 个的限制；搜索覆盖整个素材库。方向键及 Home / End 可在图片按钮聚焦时导航。

- **macOS**：在设置点 **启用 macOS 光标粘贴**，根据系统提示授予辅助功能权限。打开面板前记住当前应用，选择表情后恢复该应用并发送 `⌘V`。不自动按回车发送消息。
- 未授予辅助功能权限：依然复制完整原文件，回到聊天窗口自行按 `⌘V`。
- **Windows / Linux**：目前提供原文件复制及拖出；选择表情后回到聊天软件按 `Ctrl+V`。尚未实现自动恢复光标并粘贴。
- 关闭主窗口后应用继续留在托盘并收集。右键托盘 → **退出表情仓** 才会退出。

目标聊天软件决定粘贴结果是动画、文件附件还是原生表情。粘贴到当前应用不等于能写入任意控件，接收方必须支持图片文件粘贴；自动粘贴不是直接发送。

## 自动导入支持情况

| 来源       | 接入方式                                        | 范围与限制                                                                                                                               |
| ---------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| QQ         | 自动发现 `personal_emoji/Ori`，每 30 秒增量检查 | Mac 已实测个人收藏原件；跳过 Thumb 缩略图。未缓存的收藏需先在 QQ 收藏面板打开；Windows/Linux 路径适配为实验性                            |
| 微信       | macOS / Windows 随附 wxemoticon 0.3.0 助手      | 首次退出原微信，在助手打开的微信副本中登录并打开表情面板；首次成功后每 5 分钟同步。Windows 需保持微信 4.x 登录；Linux 可手动导入导出目录 |
| 抖音       | 独立官方网页窗口登录，观察已加载的收藏列表响应  | 打开私信的收藏表情面板并向下滚动，按页自动收集；不是无人值守全量同步。页面登录、接口变动、网络和风控可能影响结果                         |
| 本地文件夹 | 关联目录，每 30 秒检查                          | 跨平台；应用运行期间有效                                                                                                                 |

### macOS 目录授权

如果 QQ 或微信显示「需要授权」，点对应的 **授权目录**，在系统文件夹选择框中允许读取默认的数据目录。如果微信提示助手缓存权限，另点 **授权助手缓存**，选择默认的 `export-wechat-emoji` 目录；这是助手密钥 / URL 缓存，和微信原件数据目录是两处独立授权。应用没有权限时会保留已有表情并提示，不把失败显示为完成。

### 微信首次接入

1. 先正常退出微信。
2. 点 **读取微信收藏**，初次复制和准备微信副本可能需要一分钟。
3. 如弹出微信副本，完成登录并打开表情面板，等待下载与导入。
4. 若提示超时或失败，可重试；`connector-cache/wechat/<账号>/import.log` 保存脱敏后的助手错误尾部，便于本机排查。不要把密钥文件提交到仓库或公开问题中。

助手会在本机复制、重签名并运行微信副本，不修改原微信安装；数据库密钥保存在本机。第三方助手来源、版本、校验与许可证信息见 [NOTICE](vendor/wxemoticon/NOTICE.md)。该流程不是微信官方开放接口，客户端更新可能使其失效。

### 抖音导入

点 **打开抖音并收集**，等待页面加载并登录；打开私信收藏表情面板，向下滚动以加载更多。应用只处理 `CUSTOM_STICKER_PAGE` 的收藏响应，不发送聊天消息，不导入桌面客户端 Cookie。登录会话在本机独立保存。

动态表情只下载动画地址；动画下载失败或返回静态图时标记失败，不使用缩略图冒充动画。关闭导入窗口后停止接收新列表。

## 大图库与回收站

主素材库、菜单栏面板只创建屏幕附近的卡片。可见图片直接读取原件，动图正常播放；离屏图片停止加载，滚动回来时恢复预览。收藏、使用记录和 OCR 更新采用局部数据更新，尽量保留当前图片节点和滚动位置，不把原件变成静态缩略图。

- **移到回收站** 保留原件、名称、标签、收藏和 OCR 记录；可以在提示条 **撤销删除**，也可从侧栏 **回收站** 单张或批量恢复。
- 回收站不自动清空。占用空间会单独显示；**交给系统废纸篓** 需要确认，使用操作系统废纸篓接口，不直接永久删除文件。系统废纸篓不可用时保留失败项并显示原因。
- 回收站清理前会保存本机元数据恢复点。若系统已移动文件但记录保存失败，会提示先从系统废纸篓找回原件后再恢复。
- 自动收集不会拉回回收站里的同一图片。手动重新导入、导入 ZIP 或手动 WebDAV 合并仍可能恢复同一内容，沿用“不传播删除”的同步规则。
- ZIP 完整备份与 WebDAV 仅包含当前素材库中的原件，**不包含回收站原件**；需要迁移的图片请先恢复到素材库。

## 导入诊断

主窗口点 **导入诊断**，或导入后点 **查看最近导入结果**。图片 / 文件夹导入记录保留最近 20 次，原始路径与错误详情只存在本机，不加入 ZIP 或 WebDAV。

可按新增、恢复、重复、跳过、失败筛选，搜索文件名、路径或原因；支持定位原文件及重试失败项。目录不存在、权限拒绝、空文件、超过 100 MB、格式不支持、隐藏项、符号链接和目录层级限制分别记录。一处目录失败不阻断其他正常文件。

单次最多保存 20000 条明细，优先保留失败与跳过项，另显示完整总数及省略数量。自动收集没有变化时不产生空记录，相同失败短期去重。ZIP / WebDAV 的进度与错误仍显示在设置里的备份面板。

平台接入提供按系统区分的处理建议：Windows 微信 4.x 与 QQ NT 数据目录、macOS 微信副本和缓存授权、Linux 限制、抖音白屏或尚未加载收藏面板等。

## 完整备份与跨平台迁移

打开 **设置 → 完整备份与迁移**：

1. 点 **导出完整备份**，选择保存位置，得到一个 ZIP 文件。
2. 在另一台 Mac、Windows 或 Linux 设备安装表情仓，点 **导入备份并合并** 选择 ZIP。
3. 应用先校验清单、文件哈希和真实图片格式，再显示数量及配置合并选项，确认后才导入。现有原件不删除，同一图片按内容去重。

备份包含全部原件（GIF / APNG / WebP 动画保持原始字节）、名称、标签、收藏、排序、使用记录、OCR 记录、OCR 开关，以及目录和平台接入的迁移提示。WebDAV 地址和用户名也可迁移，**密码、Cookie、微信密钥和登录态不进入备份**。

本机目录、平台授权和系统登录自启不能直接搬到另一系统：导入后在迁移提示里查看原配置，再在此设备重新关联或授权。不会把其他设备的路径直接加入自动扫描，也不会替你打开系统自启。已有 WebDAV 连接不被备份中的连接替换；新设备导入地址后仍需填写密码。

导入 / 同步只合并图片，不传播删除。重复图片的手动编辑按字段修改时间合并；旧版本没有修改时间的标签取并集、收藏保留。使用与移动顺序记录取较新值，完成的 OCR 记录会保留，避免重复识别。便携设置保留较新的明确修改；可在导入确认框取消合并便携设置。

合并前会在素材库 `vault/recovery/` 保存本机元数据恢复点，原件只增加或修复，不清空。恢复点是配置 JSON，正式完整迁移请使用导出的 ZIP。备份格式当前为 `stickervault-backup` v1；清单位于 `manifest.json`，原件位于 `originals/`。单图上限 100 MB，总原件上限 20 GB，导入还会检查可用磁盘空间。

## WebDAV 手动同步

在 **设置 → WebDAV 手动同步** 填写最终的目录地址（如 `https://example.com/dav/StickerVault/`）、用户名和服务商提供的应用密码。

- 点 **保存连接** 仅保存配置，不联网同步；没有定时同步、后台同步或同步间隔。
- 点 **测试连接** 验证读写与条件写入，会在指定目录短暂创建并删除一个随机测试文件。新目录可创建，但其父目录需存在。
- 点 **手动同步** 才开始：先下载远端备份，校验后合并本机，再上传合并结果。本机为空时会取回远端图片；远端为空时保留本机图片。两边都为空时不上传空包。
- 使用目录中的 `stickervault-v1.zip`，请让需要共享的设备配置同一目录。每次传输完整备份，可看进度或点 **取消同步**；同步期间新产生的修改在下一次手动同步时带上。
- 远端文件必须返回强 ETag，服务器必须正确支持 `If-Match` / `If-None-Match`。冲突时重新下载并合并，连续冲突三次则停止，不强行覆盖。缺少 ETag、条件写入保护、备份损坏或请求失败时不使用空内容替代远端。
- 删除只影响本机：再次同步可能从另一端取回被删除的表情；目前没有远程删除或清空功能。
- 密码通过 Electron `safeStorage` 在本机保护。系统安全存储不可用（例如 Linux `basic_text` 后端）时只保留在当前进程，不明文写盘，退出后需重新输入。点 **忘记密码** 可清除保存的密码。

不自动跟随服务器重定向，也不关闭证书校验。若遇到重定向，请填写最终 WebDAV 目录地址。连接测试使用临时文件；实际图片只会在点击手动同步时传输。尚未针对所有 WebDAV 服务商实测，需在自己的服务器执行连接测试。

## 后台 OCR 自动标签

在 **设置 → 后台 OCR 自动标签** 控制识别，默认开启。随安装包附带本地简体中文和英文模型，识别过程中不上传图片，也不需要下载模型。启动约 10 秒后开始，每次处理一张、两张之间至少间隔约 2 秒，识别进程使用较低优先级；可随时暂停，正在识别的一张会完成后暂停。应用退出后停止处理，下次启动接着处理剩余图片。

- 从识别文字提取最多 8 个标签，与已有标签合并；识别全文也能被搜索。可以在详情中查看 OCR 文字，修改或删除不准确的标签。
- 按原件内容哈希保存处理记录。同一图片只自动尝试一次；没有文字、单张失败或上次中断也会记住，重启、重新导入不会反复处理。引擎启动失败不消耗图片任务，可点“继续处理剩余图片”。
- 动图仅取一帧生成临时识别图；不改写原件、预览、复制或导出，动画保留。后续帧的文字可能识别不到。
- 小字、花字、繁体、模糊图片和复杂背景可能识别不准；这是文字标签功能，不会识别人脸或自动理解图片情绪。

## 登录后自动启动

在 **设置 → 登录后自动启动** 开启或关闭，默认关闭。登录系统桌面后在菜单栏 / 系统托盘后台运行，不主动弹出主窗口；点击图标或快捷键打开面板。

| 平台    | 实现与设置                                                                                                                                                                                    |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS   | 系统登录项；系统要求批准时显示“打开系统启动设置”，按提示允许。                                                                                                                                |
| Windows | 当前用户登录启动项，无需管理员权限；如果在系统启动应用中被禁用，设置会提示。                                                                                                                  |
| Linux   | 当前用户 `$XDG_CONFIG_HOME/autostart/stickervault.desktop`（默认 `~/.config/autostart/`），需要支持 XDG 自启动的桌面环境。AppImage 记录原始 AppImage 路径，移动后需在设置点“更新启动项位置”。 |

开发模式不注册启动项，需使用已安装的版本。Linux 仅维护本应用创建的启动文件，不覆盖其他工具的同名配置。关闭此开关会撤销本应用登记的启动项。

## 动图与数据

- 支持 GIF、PNG/APNG、JPG、WebP，按文件内容识别，扩展名错误也能处理。
- 保存、复制、拖出、导出不重编码、不压缩，保留原始文件字节；动态预览直接读取原件。
- 暂不把动态 WebP/APNG 转成 GIF；接收软件不支持时可导出原件。
- SHA-256 内容去重。单文件不超过 100 MB，目录递归深度不超过 12。
- QQ、抖音记忆已处理条目，手动移除后不会每次扫描重新出现；微信下载缓存和普通关联目录可能再次导入已移除项目，可先停用来源。
- 「最近使用」指在表情仓中的使用操作，不读取其他聊天软件的发送历史，也不能判断拖拽是否最终成功发送。

素材库位于 Electron `userData` 目录下的 `vault/`。macOS 初始版本通常位于 `~/Library/Application Support/表情仓/vault/`，包含 `library.json`、`originals/` 和 `connector-cache/`。退出应用后复制整个目录可备份；只导出图片不会备份标签与常用状态。

原件和元数据本地保存，无云同步、广告或统计服务。启用平台接入时会访问对应的官方网站或图片 CDN；构建或准备微信助手时会访问 GitHub。

## 开发

### 环境与启动

- Node.js **24 LTS**（最低 22.12）与 npm。
- macOS 的原生剪贴板助手需要 Xcode Command Line Tools：`xcode-select --install`。
- Windows 支持微信 4.x 助手；Linux 暂不提供微信自动读取，可使用手动导入。

```sh
git clone https://github.com/DanZai233/sticker-vault.git
cd sticker-vault
npm ci
# macOS / Windows 下载对应助手并校验 SHA-256；Linux 跳过
npm run prepare:helper
# macOS 编译原文件复制 / 辅助功能粘贴助手；其他系统跳过
npm run build:native
npm run prepare:ocr
npm start
```

开发时 `vendor/` 中下载或编译的二进制不会提交 Git。Electron 下载及助手下载需要网络。

### 常用命令

```sh
npm run prepare:ocr          # 准备随包附带的离线中英文模型
npm run test:desktop         # 独立临时素材库验证真实 IPC、回收站与诊断
npm run test:backup-engine   # Electron 内完整备份与本机 WebDAV 协议集成
npm run test:ocr-engine      # 真实 OCR 引擎集成验证（不读取个人素材）
npm run test:platform-ui     # 平台设置与快捷面板回归
npm run check                # 语法检查与 Node 测试
npm test                     # 数据保真、去重、QQ 原件定位、抖音解析与域名校验
npm run prepare:helper -- darwin arm64
npm run build:native -- arm64
npm run dist -- --mac --arm64 --publish never
npm run dist -- --mac --x64 --publish never
npm run dist -- --win --x64 --publish never
npm run dist -- --win --arm64 --publish never
npm run dist -- --linux --x64 --publish never
npm run dist -- --linux --arm64 --publish never
```

请在目标系统构建相应安装包；如需交叉构建，请使用下述 GitHub Actions 矩阵。编译 macOS 助手时架构必须与安装包一致。产物在 `dist/`，执行 `node scripts/checksums.cjs` 生成 SHA-256 清单。


## GitHub Actions 与发布

`.github/workflows/build.yml` 在推送 `main`、PR、手动运行和推送 `v*` 标签时构建：macOS arm64/x64、Windows x64/arm64、Linux x64/arm64，共 6 组。

流程使用 `npm ci` → 测试 → 校验下载相应架构助手 → 准备离线 OCR 模型及真实引擎集成验证 → 编译原生助手 → electron-builder 打包 → SHA-256 → 上传 Artifacts。普通构建只需仓库读取权限，标签发布任务才获得 `contents: write`；不需要配置个人访问令牌或签名证书。

发布新版本：先修改 `package.json` 与锁文件中的版本，并更新 [CHANGELOG](CHANGELOG.md)，提交后推送标签：

```sh
npm version 0.3.1 --no-git-tag-version
git add package.json package-lock.json CHANGELOG.md
git commit -m "chore: release 0.3.1"
git tag v0.3.1
git push origin main v0.3.1
```

全部 6 组成功后，标签任务自动创建 GitHub Release 并附上安装包及校验和；失败时不会发布部分安装包。手动重跑同一标签会更新同名附件。

构建成功不代表微信 / 抖音真实账号、系统权限和各聊天软件拖拽已通过验收。测试覆盖和已知限制见 [开发与测试说明](docs/DEVELOPMENT.md)。

### Windows 微信路径与界面（0.3.4）

读取微信收藏会检查 `%USERPROFILE%\xwechat_files`、系统实际文档目录（支持 OneDrive / 重定向）下的 `xwechat_files`，以及微信配置中记录的自定义位置。也可以点「选择数据目录」，选择 `xwechat_files`、其中的账号文件夹或其父目录。账号根据表情数据库识别，不要求文件夹以 `wxid_` 开头。

找不到目录时，在微信「设置 → 文件管理」查看位置。自动读取面向微信 4.x；旧版目录不能当作 4.x 数据库。Windows 需保持微信登录并打开表情面板，不需要退出微信或启动 macOS 副本。Windows ARM64 包使用 x64 助手，依赖系统的 x64 仿真；真实 ARM64 微信进程兼容性尚未实机验收。

Windows 隐藏 macOS 光标粘贴和助手缓存授权，托盘面板复制原文件后使用 Ctrl+V。真实账号读取仍需用户电脑验收，CI 验证路径、界面、助手启动及安装包资源。

### Windows QQ NT 数据目录

自动检查系统实际文档目录（含 OneDrive / 重定向）中的 `Tencent Files`、`QQ Files`，以及 AppData 下的 QQ NT 账号目录；支持 QQ 用户配置 `UserDataInfo.ini` 记录的自定义位置。可以选择数据父目录、QQ 账号目录、`nt_qq`、`nt_data`、`Emoji`、`personal_emoji` 或其中的 `Ori` 文件夹。只读取收藏的 Ori 原件，不导入 Thumb 缩略图、聊天收到的图片或程序自带表情。旧版 QQ 数据库 / EIF 文件尚不支持自动解析。
